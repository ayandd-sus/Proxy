# SillyTavern ↔ AITUNNEL: Claude proxy с prompt caching

Инструкция сверена **1 октября 2026 года**. Прокси поддерживает оба способа подключения SillyTavern, но основная инструкция ниже рассчитана на ваш вариант: **Anthropic-модель через Custom (OpenAI-compatible) Chat Completion**.

## Что делает прокси

- Для OpenAI-compatible клиента принимает `POST /v1/chat/completions`, добавляет cache-параметры AITUNNEL и пересылает запрос на тот же маршрут AITUNNEL. Внутри этого маршрута формат Anthropic↔OpenAI преобразует сам AITUNNEL, не локальный прокси.
- Для встроенного источника SillyTavern **Claude** принимает нативный `POST /v1/messages`, преобразует локальный `x-api-key` в документированный AITUNNEL `Authorization: Bearer` и сохраняет формат Anthropic Messages.
- Для Claude добавляет верхнеуровневый `cache_control`, если клиент ещё не прислал явные cache-маркеры; сохраняет уже выставленные маркеры.
- По умолчанию добавляет непрозрачный HMAC `session_id` для привязки повторных запросов диалога к провайдеру AITUNNEL.
- Передаёт SSE-стрим без преобразования событий и выводит cache read/write-счётчики, если AITUNNEL вернул их.

Промпт не сохраняется и не пишется в логи. Чтобы добавить поля к JSON, прокси буферизует запрос в памяти, затем отправляет его в AITUNNEL.

## 1. Запустить прокси

Нужен **Node.js 20+**. Сторонние npm-пакеты не нужны.

1. Скопируйте `.env.example` в `.env`.
2. Впишите ключ AITUNNEL. Создайте отдельный локальный ключ для SillyTavern:

   ```bash
   node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
   ```

   Пример `.env`:

   ```dotenv
   AITUNNEL_API_KEY=sk-aitunnel-ВАШ_КЛЮЧ
   PROXY_API_KEY=СЮДА_СЛУЧАЙНАЯ_СТРОКА_ИЗ_КОМАНДЫ
   AITUNNEL_BASE_URL=https://api.aitunnel.ru/v1
   PROXY_HOST=127.0.0.1
   PROXY_PORT=8787
   CACHE_MODE=auto
   CACHE_TTL=5m
   SESSION_AFFINITY=on
   ```

   `AITUNNEL_API_KEY` остаётся в `.env`; в поле API key SillyTavern нужно ввести **`PROXY_API_KEY`**, а не ключ провайдера.

3. Запустите сервис из каталога репозитория:

   ```bash
   npm start
   ```

   Проверка запуска: `http://127.0.0.1:8787/healthz` должна вернуть `{"status":"ok"}`. Тесты: `npm test`.

## 2. Подключить AITUNNEL в вашем режиме OpenAI-compatible

В SillyTavern:

1. Откройте **API Connections** и выберите именно **Chat Completion**, не Text Completion.
2. Источник: **Custom (OpenAI-compatible)**.
3. Укажите:
   - **Custom Endpoint / Base URL:** `http://127.0.0.1:8787/v1`
   - **API Key:** значение `PROXY_API_KEY` из `.env`
   - **Model:** точный ID Claude из каталога AITUNNEL, например `claude-sonnet-4.6`.
4. Нажмите **Connect**. Если модель не появилась в списке, введите её ID вручную.

Не добавляйте в URL `/chat/completions` и не ставьте завершающий `/`: SillyTavern добавляет маршрут сам. В этом режиме **не** включайте `Use a reverse proxy` из источника Claude — это настройка другого API-подключения.

Если SillyTavern работает в Docker, адрес `127.0.0.1` внутри контейнера указывает на сам контейнер. Используйте адрес хоста, доступный из контейнера (часто `host.docker.internal`), или общий Docker network. Чтобы прокси слушал не только loopback, задайте `PROXY_HOST=0.0.0.0`; не публикуйте его в интернет без TLS и firewall.

### Если решите переключиться на нативный Claude connector

Прокси также поддерживает его: выберите **Chat Completion → Claude**, включите **Use a reverse proxy**, задайте URL `http://127.0.0.1:8787/v1` и Proxy Password `PROXY_API_KEY`. ST сам добавит `/messages`. Эта инструкция приведена как запасной вариант; для вашей текущей OpenAI-compatible схемы используйте предыдущий раздел.

## 3. Как поставить и включить Freaky Frankenstein

Похоже, ваша ссылка ведёт к посту об **FF5.4 Internal States**. Короткую Reddit-ссылку в этой среде открыть не удалось (Reddit вернул 403), поэтому ниже опираюсь на [официальный архив](https://rentry.org/freaky-frankenstein-presets) и [объявление FF5.4](https://www.reddit.com/r/SillyTavernAI/comments/1w49lyx/preset_update_freaky_frankenstein_54_the_second/). На 01.10.2026 архив указывает FF5.4 как опубликованную версию; FF6 Micro там всё ещё помечен **Coming Soon**.

1. В архиве выберите **Freaky Frankenstein 5.4 → Internal States** — стандартный вариант для SillyTavern. Не берите вариант **Marinara Engine Agentic**, он предназначен для другого frontend. Вариант **FR / Hapuppy Forced Reasoning** нужен не для обычного Claude-подключения.
2. Включите Chat Completion в API Connections.
3. Откройте панель **AI Response Configuration** (иконка ползунков, первая слева), нажмите **Import preset** и выберите скачанный JSON. После импорта выберите FF5.4 в списке активных пресетов. Если импорт сообщает, что подходящих секций нет, проверьте, что вы не в Text Completion и открыли именно панель Chat Completion Presets.
4. В **API Connections → Chat Completion → Prompt Post-Processing** выберите **Semi-strict (alternating roles; no tools)** — автор FF5.4 рекомендует полустрогое чередование ролей без tools.
5. В панели **Advanced Formatting** (иконка `A`) снимите **Trim incomplete sentences**. Автор предупреждает, что эта настройка может обрезать внутренние XML-теги FF.
6. Сначала оставьте импортированные параметры и переключатели как есть. FF5.4 по умолчанию ориентирован на **BOLT**. Не включайте одновременно разные режимы Chain of Thought (например, BOLT, Micro и MAX) и не включайте все дополнительные модули разом. В самом пресете есть подсказки/README у переключателей — откройте их перед изменением.
7. Проверьте **Extensions → Regex**. Для FF5 требуется **FF5 Regex 3.0**; архив пишет, что он обычно включён/поставляется с пресетом и даёт отдельную ссылку на резервную загрузку. Если профиль не появился или правила не импортировались, скачайте Regex 3.0 из [официального архива](https://rentry.org/freaky-frankenstein-presets) и импортируйте его. Не импортируйте один и тот же набор повторно: дубли правил могут испортить форматирование.
8. Начните новый тестовый чат с персонажем. Карточка персонажа и пресет — разные вещи: пресет задаёт инструкции/параметры, а карточку импортируют отдельно.

Если ответы слишком долгие или модель теряет персонажа, не включайте дополнительные блоки наугад: FF5.4 сам предупреждает, что меньшим моделям нужно меньше Internal States. Сначала выключайте необязательные модули по одному или выберите более лёгкий режим из README пресета.

## 4. Кэширование именно при OpenAI-compatible подключении

В вашем режиме SillyTavern отправляет OpenAI-compatible Chat Completion, поэтому встроенные параметры **`claude.enableSystemPromptCache`** и **`claude.cachingAtDepth`** SillyTavern не управляют этим запросом. Прокси делает нужное автоматически: для Claude добавляет `cache_control` верхнего уровня на `/v1/chat/completions`. Ничего дополнительно добавлять в Custom Body Fields не нужно.

- По умолчанию `CACHE_MODE=auto`, `CACHE_TTL=5m`.
- `CACHE_TTL=1h` задаёт более долгий TTL; запись часового кэша у AITUNNEL дороже.
- `CACHE_MODE=off` выключает только маркер, добавляемый прокси. Уже имеющийся явный маркер он не удаляет.
- `SESSION_AFFINITY=on` добавляет стабильный непрозрачный `session_id`; можно выключить через `SESSION_AFFINITY=off`.

После двух достаточно длинных последовательных запросов смотрите терминал прокси: при наличии счётчиков будет строка `cache usage model=... read=... write=...`. Обычно первая отправка пишет кэш (`write`), следующая может читать его (`read`). Порог зависит от модели; короткий промпт, изменившийся префикс или истёкший TTL могут не дать cache hit.

FF5.4 Regex может удалять старые блоки Internal States из истории, экономя контекст. Но заявление автора о сокращении количества токенов **не равно** гарантированному cache hit: для чтения кэша AITUNNEL важны точное совпадение префикса, размер кэшируемого участка и время между запросами.

### Regex: что реально может сломать префикс

В SillyTavern область применения правила задаётся двумя независимыми вещами (см. `public/scripts/extensions/regex/engine.js`, ветка `release`):

| Поле | Значение | К чему применяется |
| --- | --- | --- |
| `placement: 0` | `MD_DISPLAY` | устарело |
| `placement: 1` | `USER_INPUT` | отправленный текст пользователя |
| `placement: 2` | `AI_OUTPUT` | ответы модели в истории |
| `placement: 3` | `SLASH_COMMAND` | подстановки slash-команд |
| `placement: 5` | `WORLD_INFO` | записи World Info |
| `placement: 6` | `REASONING` | блок reasoning |

Отдельного placement «исходящий промпт» не существует — его включает флаг **Alter Outgoing Prompt** (`promptOnly` в JSON): в движке это `script.promptOnly && isPrompt`, правило выполняется при сборке промпта для модели. Флаг **Only for Display** (`markdownOnly`) — это `script.markdownOnly && isMarkdown`: правило меняет только отрисовку и **не может** изменить то, что уйдёт в API.

Разбор прилагаемого `FF5 Regex 3.0 Suite.json` (25 правил):

- **20 правил** с `markdownOnly: true` — только отображение. На префикс и на cache read не влияют.
- **5 правил** с `promptOnly: true` действительно правят исходящий промпт: `FF5 Delete - Untagged Thoughts`, `FF5 - Context Saver (Universal)`, `Hapuppy Delete Thoughts`, `FF5 - GFX Stripper`, `FF5 - Image Prompt Stripper`.
- Из этих пяти только **`FF5 - Context Saver (Universal)`** ограничено по глубине: `minDepth: 2`.

По [документации SillyTavern](https://docs.sillytavern.app/extensions/regex/) глубина считается от конца: `0` — последнее сообщение, `1` — предпоследнее, `2` и больше — всё, что старше. Глубина конкретного сообщения меняется каждый ход: то, что было `1`, становится `2`. Значит правило с `minDepth: 2` вырезает блок `<!-- GFX_START -->` / `<internal_states>` из сообщения **не сразу, а когда оно отойдёт на два хода назад**. Текст уже отправленного сообщения меняется между двумя запросами, префикс перестаёт совпадать, и AITUNNEL перезаписывает кэш целиком — ровно та картина, когда `write` есть, а `read` нет.

Порядок правил усиливает эффект: `Context Saver` (№3) выполняется раньше `GFX Stripper` (№23, `minDepth: 0`). На глубине 0–1 работает только №23 и содержимое GFX-блока сохраняется, а на глубине ≥2 срабатывает №3 и удаляет блок целиком, вместе с содержимым.

Остальные четыре `promptOnly`-правила от глубины не зависят (`minDepth: null` или `0`) и обрабатывают сообщение одинаково в любой позиции, поэтому сами по себе префикс не «шатают».

Что делать — **не отключайте весь набор Regex и не трогайте пресет**: 20 правил из 25 к запросу не относятся вообще. Достаточно убрать «плавающую» границу у одного правила:

1. В **Extensions → Regex** откройте **FF5 - Context Saver (Universal)** и поставьте **Min Depth** в `0` (или очистите поле). Блоки Internal States будут вырезаться из всех сообщений одинаково, и префикс станет стабильным. Минус: модель перестанет видеть Internal States двух последних ответов.
2. Если это ломает логику пресета — выключите тумблером только это одно правило. Префикс тоже стабилизируется, но Internal States останутся в истории целиком и промпт вырастет.
3. После изменения начните **новый** тестовый чат: кэш привязан к уже отправленному префиксу, старую историю это не починит.

### Что прислать для диагностики

Две подряд идущие строки терминала прокси из одного чата:

```text
[proxy] cache usage model=claude-… read=0 write=9874
[proxy] cache usage model=claude-… read=0 write=10231
```

Нужны только `model`, `read` и `write` — без API-ключей и без текста промпта. Строка печатается, только если AITUNNEL вернул cache-счётчики; если её нет вообще, счётчиков не было (частая причина — промпт короче порога модели: 1024 токена для Sonnet 4/4.5/4.6 и Opus 4/4.1, 4096 для Opus 4.5+ и Haiku 4.5).

Решающий эксперимент — отправьте два сообщения **одно сразу за другим, с паузой меньше минуты**:

- `write=N, read=0` → `read` близко к `prompt_tokens`, `write` заметно меньше `N` — префикс стабилен, кэш работает.
- `write=N, read=0` → `write=M, read=0` при `M > N` — префикс перезаписывается каждый раз. Причина в меняющемся содержимом истории (см. правило с `minDepth: 2`), а не в TTL.
- Если при паузе меньше минуты появляется `read > 0`, а при обычной паузе — нет, то префикс в порядке и дело в TTL: по умолчанию `CACHE_TTL=5m`, кэш живёт 5 минут с последнего обращения.

`CACHE_TTL=1h` продлевает кэш, но запись часового TTL у AITUNNEL стоит примерно 2× цены входа против ~1.25× для 5 минут. Переключать его имеет смысл, только если префикс уже стабилен, а паузы между ходами длиннее пяти минут: сломанный префикс часовой TTL не лечит.

### Диагностика префикса: `PREFIX_DIFF_LOG`

Две строки `read`/`write` показывают **факт** промаха, но не его причину. Чтобы увидеть причину, включите в `.env`:

```env
PREFIX_DIFF_LOG=on
```

Прокси начнёт печатать, что произошло с кэшируемым префиксом между двумя соседними запросами:

```text
[proxy] session fingerprint=3f9c1a02 (baseline)
[proxy] prefix baseline segments=42
[proxy] session fingerprint=3f9c1a02 (stable)
[proxy] prefix GREW ONLY segments=42 -> 44 (shared prefix intact; cache should hit)
```

Возможные варианты строки `prefix`:

- `GREW ONLY` — общий префикс не изменился, дописался только хвост. Это здоровый случай: кэш должен читаться.
- `REWRITTEN at msg[17] role=assistant …` — сообщение с этим индексом изменилось между запросами. Индекс считается от начала (`msg[0]` — первое сообщение после system). Если индекс «гуляет» относительно конца чата, виновато правило Regex с ограничением по глубине.
- `unchanged` — запрос идентичен предыдущему.

Отдельно печатается `session fingerprint`. По [документации AITUNNEL](https://aitunnel.ru/docs/caching) кэш живёт у конкретного провайдера, а привязка держится на `session_id`. Если fingerprint между ходами меняется, привязка может сбрасываться — и тогда кэш пишется на одном провайдере, а читается на другом.

Диагностика хранит в памяти только короткие хеши предыдущего запроса (8 hex-символов на сегмент) и сам `session_id` не покидает процесс. Текст промпта не сохраняется и не печатается. Режим выключен по умолчанию; верните `PREFIX_DIFF_LOG=off`, когда он больше не нужен.

Дополнительные поля в строке `prefix`:

- `roles=system:1,user:12,assistant:11` — перепись ролей. Если счётчик `assistant` не растёт, ответы модели не уходят отдельными сообщениями и стабильного префикса не возникает в принципе.
- `size` — размер сегмента в символах (сериализованный JSON, не текст промпта). Если при `REWRITTEN` размер **не изменился**, внутри сегмента стоит динамическое значение — макрос времени, даты или `{{random}}`. Если размер растёт — история дописывается в то же сообщение.

### Нестабильный `session_id`

Отдельная и независимая причина отсутствия cache hit. Строка

```text
[proxy] session fingerprint a5b63d6a -> ad0b2d2e (CHANGED: AITUNNEL provider affinity may reset)
```

означает, что `session_id` меняется от запроса к запросу. По [документации AITUNNEL](https://aitunnel.ru/docs/caching) кэш живёт у конкретного провайдера, а привязка держится на `session_id`: с первого успешного запроса — если `session_id` задан. Если он меняется каждый ход, кэш пишется на одном провайдере, а читается на другом.

Изначально прокси выводил `session_id` из связки «модель + system + первое не-системное сообщение». В коротком чате первое не-системное сообщение — это **и** последнее, и SillyTavern переписывает его каждый ход, поэтому идентификатор менялся на каждом запросе. Теперь якорь — это **модель + system-промпт**, который между ходами стабилен. Если system-промпта нет, прокси по-прежнему опирается на первое сообщение.

Если system-промпт тоже содержит динамику (макросы даты/времени) или вы хотите гарантии, задайте идентификатор явно в `.env`:

```env
SESSION_ID=my-sillytavern-aitunnel-session
```

Одно значение на один экземпляр SillyTavern, не длиннее 256 символов. Разные диалоги при этом пойдут к одному провайдеру — это нормально: сам кэш привязан к префиксу, а не к `session_id`, поэтому пересечений не будет.

### Когда последнее сообщение перезаписывается: `CACHE_MODE=history`

Инструкции могут приклеиваться к **последнему** user-сообщению, а на следующем ходу переезжать на новое. Тогда в логе видно характерное «сдувание»:

```text
prefix REWRITTEN at msg[3] role=user … (segment size 8488 -> 50, total 30713 -> 32936)
```

Сообщение было 8488 символов, стало 50 — при этом ассистентские сообщения не меняются. Это не Regex: это SillyTavern каждый ход заново собирает блок инструкций вокруг последнего хода. Автоматический верхнеуровневый `cache_control` ставит точку на **последний** кэшируемый блок, то есть включает в префикс это меняющееся сообщение — и кэш не читается никогда.

Что делать, по порядку:

1. **Найдите блок.** Откройте **AI Response Configuration → Post-History Instructions (jailbreak)** и **Extensions → Chat Injections**. Ищите поле размером около 8–9 тысяч символов — именно столько «сдувается». Если такое найдётся, перенесите его содержимое в **Main Prompt / System Prompt**: там оно станет частью `msg[0]` и перестанет двигаться. Это самое чистое решение.
2. **Если переносить не хотите**, исключите последнее сообщение из кэшируемого префикса:

```env
CACHE_MODE=history
```

Прокси поставит явную точку на сообщении **перед** последним, и тогда кэшироваться будет вся история до него — а она между ходами стабильна. Режим работает и на `/v1/chat/completions`, и на `/v1/messages`. Если сообщений меньше трёх, прокси вернётся к автоматическому маркеру (`cache=added-fallback` в логе).

Учтите: `CACHE_MODE=history` лечит только «плавающий хвост». Если правило Regex с `minDepth` начнёт вырезать Internal States из ассистентских сообщений, префикс снова поедет — лог покажет `REWRITTEN` уже на `role=assistant`.

### Что в итоге должно получиться

Здоровый лог выглядит так:

```text
[proxy] session fingerprint=b82182ed (stable)
[proxy] prefix GREW ONLY segments=6 -> 8 roles=system:1,user:4,assistant:3 size=32936 -> 35010 (shared prefix intact; cache should hit)
[proxy] cache usage model=claude-sonnet-5.5 read=13142 write=1074
```

Ключевые признаки: `session (stable)`, `GREW ONLY` вместо `REWRITTEN`, и главное — **`read` больше нуля**, а `write` мал.

## Маршруты, безопасность и отладка

Прокси принимает только нужные маршруты:

- `GET /v1/models`;
- `POST /v1/chat/completions` — ваш OpenAI-compatible вариант;
- `POST /v1/messages` и `POST /v1/messages/count_tokens` — нативный Claude connector;
- `GET /healthz` — локальная проверка.

`401` на локальном прокси обычно означает, что в SillyTavern введён не тот `PROXY_API_KEY`. Если локальный запрос проходит, но AITUNNEL отвечает `401`, проверьте `AITUNNEL_API_KEY` в `.env`. Для Docker проверьте, что SillyTavern может достучаться до адреса и порта прокси. Остальные пути намеренно возвращают `404`.

По умолчанию прокси слушает только `127.0.0.1`, ограничивает тело запроса 128 MiB и не сохраняет историю промптов. Не коммитьте `.env` и не отправляйте его содержимое в чат.
